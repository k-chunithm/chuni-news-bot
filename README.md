CHUNITHM（チュウニズム）の[公式サイト ニュース一覧](https://info-chunithm.sega.jp/)を監視して新しいニュースを自動転送する機能に加え、ナビゲーターキャラクター「ユニちゃん」としてユーザーと対話するAI会話機能を備えたDiscord Botです。
Groqの API を利用し、楽曲の定数データや最新のイベント情報を調べながら楽しく会話してくれます。

## 技術スタック
- **言語:** Python 3
- **主要なライブラリ:**
  - `discord.py` (Discord Botとしての基盤・コマンド処理)
  - `groq` (Groq APIによる高度なAI会話とTool Use)
  - `google-cloud-vision` (Google Cloud Vision APIを用いたリザルト画像の文字認識)
  - `beautifulsoup4` (公式サイトの解析・Web検索結果の解析)
  - `httpx` / `cloudscraper` (HTTP通信・スクレイピング時のWAF回避)
  - `python-dotenv` (環境変数の管理)

## 動作の仕組み
### 1. ニュースの自動転送
1. 10分に1回、公式ニュースサイトを確認し、最新の記事URLを取得します。
2. 取得したURLが前回取得したもの（`last_news_url.txt` に保存）と異なる場合、「新しいニュース」と判定します。
3. 記事のタイトル、URL、サムネイル画像を抽出し、登録されているすべてのDiscordチャンネルへ埋め込みメッセージ（Embed）として一斉送信します。

### 2. キャラクター（ユニちゃん）とのAI会話＆Web検索・画像認識
1. メンションや返信、あるいは指定した会話チャンネルで発言すると、AIモデル（Groq / openai/gpt-oss-20b等の推論モデル）を通してユニちゃんが返答します（思考プロセスは自動的に非表示になります）。
2. チュウニズムの楽曲定数などは、ローカルのデータ（`prompt_cache/chunithm_const_data.txt`）をAIが自律的かつあいまい検索を用いて調べて回答します。（「6兆年」などの略称や「MUSIC PЯAYER」などの表記揺れにも対応！）
3. イベント情報など、最新のWeb情報が必要な場合はBotが自律的にDuckDuckGo検索（Tool Use）を行い、最新の情報を取得してから回答します。
4. ユーザーの発言にネットスラング（語録など）が含まれる場合、ユニちゃんの明るいキャラクター性を維持しつつノリ良く返答します。
5. **チュウニズムのリザルト画面の画像を送信すると、Google Cloud Vision APIを用いて自動的にスコアやランクを解析します。「AJC」「AJ」「SSS+」「SSS」などの素晴らしいリザルトを認識すると、自分のことのように大喜びして思い切り褒めてくれます。**
   ※従量課金を防ぐため、Vision APIの利用回数をプログラム内でカウントしており、月間990回に達した場合は安全装置として翌月まで自動的に画像認識機能がストップするようになっています。（もし有料枠に入っても1000枚以上読み込ませたい場合は、`bot.py` 内の `limit = 990` の数値を手動で引き上げてください）

### 3. 定期的なリマインド機能
1. **チームブースト日通知**: 毎日00:00に、そのサーバーで登録されているチームブースト日かどうかを判定し、該当する場合は `@everyone` と専用の画像を添えてお知らせします。（月が切り替わると前月の設定は自動でリセットされます）
2. **チームブースト未設定リマインド**: 毎月10日の昼12時になってもチームブースト日が設定されていない場合、設定を促すお知らせを送信します。
3. **月末アイテム交換リマインド**: 月末の3日前の昼12時に、CHUNITHM-NETのアイテム交換忘れを防止するためのリマインド画像を送信します。

## Discord上での使い方

### スラッシュコマンド一覧
Discord上で `/` を入力することで、以下のコマンドを使用できます。

| コマンド | 説明 |
| --- | --- |
| `/news_register` | 実行したチャンネルを「ニュースの通知先」に登録します。 |
| `/news_unregister` | 実行したチャンネルでの「ニュースの通知」を解除します。 |
| `/chat_register` | 実行したチャンネルを「ユニちゃんとの自動会話（メンション不要）チャンネル」に設定します。 |
| `/chat_unregister` | 実行したチャンネルでの「自動会話設定」を解除します。 |
| `/boost_register` | カレンダーのUIから、今月のチームブースト日を4つ選んで登録します。 |
| `/boost_unregister` | 設定されているチームブースト日を解除します。 |

### 1. ニュースの自動通知
ニュースを流したいチャンネルで `/news_register` を実行してください。以降、公式サイトで新しいニュースが公開されると自動的にそのチャンネルへ通知が送信されます。

### 2. ユニちゃんとの会話
- **メンション・返信**: Bot宛にメンション（`@botの名前`）や返信をすると、いつでもAIのユニちゃんが返事をしてくれます。
- **自動会話（メンション不要）**: 特定のチャンネルでメンションなしで会話したい場合は、そのチャンネルで `/chat_register` を実行してください。
- **Web検索による回答**: 「今月の日替わりボーナスって何？」などと聞くと、自律的にWeb検索を行って最新情報を踏まえて答えてくれます！

### 3. チームブースト日の設定
サーバーごとに「チームブースト日」を管理・通知する機能です。
`/boost_register` を実行して設定すると、当日の00:00に `/news_register` で登録済みのチャンネルへお知らせ（メンション付き）が送信されます。

※ **注意事項**: チームブースト日は月ごとに変動するため、**月が切り替わると前月の設定は自動的にリセット（解除）されます**。新しい月になったら、改めて `/boost_register` で設定を行ってください。

## 必要な事前準備（ローカル実行）

### 1. パッケージインストール
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. 環境変数の設定
`.env` ファイルを作成し、以下の情報を記述します。
```env
DISCORD_TOKEN=あなたのDiscordボットトークン
GROQ_API_KEY=あなたのGroq APIキー (必須: ユニちゃんとの会話機能やWeb検索機能を使用する場合)
GOOGLE_APPLICATION_CREDENTIALS=gcp-vision-key.json (※Vision API用のGCPサービスアカウントキーのファイルパス)
```
※ 画像認識機能を利用するためには、GCPでVision APIを有効化し、取得したサービスアカウントのJSONファイルをプロジェクトのディレクトリ内に配置してください。

## クラウド（GCP / e2-micro）でのデプロイ・運用手順

### 1. GCP インスタンスの設定（無料枠の推奨設定）
GCPの「Always Free（無期限無料枠）」内で運用するための推奨設定です。

- **リージョン**: `us-west1` (オレゴン), `us-central1` (アイオワ), `us-east1` (サウスカロライナ) のいずれかを選択。
- **マシンタイプ**: `e2-micro` (2 vCPU, 1 GB メモリ)。
- **ブートディスク**:
  - タイプ: **標準永続ディスク** (Standard Persistent Disk) を選択（※バランスまたはSSDは有料になる場合があります）。
  - サイズ: 30 GB 以下。
- **OS**: Debian または Ubuntu (LTS) を推奨。
- **ネットワーク**: 「静的外部IPアドレス」を予約してインスタンスに紐付けておくと、再起動してもIPが変わらずSSH接続が楽になります。

### 2. ローカル（Mac）からのSSH接続設定（初回のみ）
GCPのブラウザターミナルを使わず、ローカルのMacターミナルから直接サーバーへ接続できるようにするための手順です。

1. **公開鍵の確認（Mac）**：Macのターミナルで `cat ~/.ssh/id_rsa.pub` を実行し、公開鍵をコピーします。
2. **公開鍵をGCPサーバーに登録**：GCPのブラウザターミナル上で、コピーした公開鍵を登録します。
   ```bash
   echo "ssh-rsa AAAAB3Nza......(あなたのMacの公開鍵の文字列)......" >> ~/.ssh/authorized_keys
   ```

### 3. GCPプロジェクトでの Vision API の有効化とサービスアカウント（認証キー）の取得
画像認識（OCR）機能を利用するために、GCP上で「Cloud Vision API」を有効化し、認証用のJSONキーを発行します。

1. [GCPコンソール - APIとサービス] から「Cloud Vision API」を検索し、有効にするボタンを押します。
   ※ Cloud Vision APIのテキスト検出機能は、毎月最初の 1,000 ユニット（画像）まで無料です。個人の身内サーバー規模であれば基本的に無料で運用可能です。
   **（注意）** 意図しない従量課金を完全に防ぐため、Botのプログラム（`bot.py`）内に「月間990回で自動的に画像認識をストップする」ストッパー機能を実装しています。もし課金してでも月に1000枚以上処理させたい場合は、`bot.py` の `limit = 990` の部分をご自身で修正してから運用してください。
2. GCPコンソールの [IAMと管理] > [サービスアカウント] へ移動します。
3. 新しいサービスアカウントを作成します（役割は特に不要ですが、念のため「Vision API ユーザー」を付与しても構いません）。
4. 作成したアカウントの「キー」タブから新しいキー（JSON形式）を作成し、手元のMac等にダウンロードします。

### 4. 初回環境・アプリのセットアップ
1. **サーバー側の必要なパッケージをインストール**
   ```bash
   sudo apt update
   sudo apt install -y python3-pip python3-venv tmux
   ```

2. **Macからファイルを転送**
   手元のMacのターミナルで実行してください。（※サービスアカウントのJSONキーファイルも含めて転送します）
   ```bash
   scp bot.py .env requirements.txt gcp-vision-key.json [ユーザー名]@[サーバーのIPアドレス]:~/chuni_news_bot/
   ```

3. **サーバーにSSH接続してアプリを構築**
   ```bash
   ssh [ユーザー名]@[サーバーのIPアドレス]
   cd chuni_news_bot

   # 仮想環境の作成
   python3 -m venv venv

   # 実行画面（tmux）の作成
   tmux new -s bot

   # 実行準備
   source venv/bin/activate
   pip install -r requirements.txt

   # Bot起動
   python3 bot.py
   ```

4. **実行状態のまま抜ける（デタッチ）**
   実行中に `Ctrl + B` → `D` を押すと、Botを動かしたままSSHを終了できます。
   （画面を閉じてもBotは動き続けます）

### 5. 2回目以降（エラー時や再起動時）
1. **サーバーに接続**
   ```bash
   ssh [ユーザー名]@[サーバーのIPアドレス]
   cd chuni_news_bot
   ```
2. **実行画面に戻る（アタッチ）**
   ```bash
   tmux attach -t bot
   ```
3. **停止・再起動**
   `Ctrl + C` で一度止めてから、`python3 bot.py` で再度実行します。

### 6. ローカルでコードを修正し、GCPサーバーに反映させる手順
ローカル（Mac）で `bot.py` や `requirements.txt` などを修正した後、その変更をサーバー上のBotに適用するための手順です。

1. **ローカルからサーバーへ新しいファイルを送信 (scp)**
   Macのターミナルで `chuni-news-bot` フォルダを開き、以下のコマンドで上書き送信します。
   （`.env` も更新した場合は含めてください）
   ```bash
   scp bot.py requirements.txt .env [ユーザー名]@[サーバーのIPアドレス]:~/chuni_news_bot/
   ```

2. **サーバーに接続して実行画面（tmux）を開く**
   ```bash
   ssh [ユーザー名]@[サーバーのIPアドレス]
   tmux attach -t bot
   ```

3. **Botを再起動する（＋必要な場合はパッケージ更新）**
   動いているBotを `Ctrl + C` で一度止めます。
   もし `requirements.txt` に新しいパッケージを追加した場合は、Botを起動する前に以下を実行してインストールします（ターミナルの左端に `(venv)` と表示されているか確認してください。表示されていない場合は `source venv/bin/activate` を実行します）。
   ```bash
   pip install -r requirements.txt
   ```
   その後、再度Botを実行します。
   ```bash
   python3 bot.py
   ```

4. **実行画面から抜ける（デタッチ）**
   起動を確認したら、`Ctrl + B` を押した直後に `D` を押し、Botを裏で動かしたままログアウトします。

### 7. スクレイピングの定期実行（楽曲定数データの自動更新）
`scraper.py` を毎日自動で実行して楽曲定数データ（`chunirec_all.json`）を最新に保つには、`bot` とは別の専用の tmux タスク（`scraping`）を作成します。
※イベント情報はBotが会話時に自律的にWeb検索を行うため、ここでのスクレイピング対象は楽曲定数のみとなります。

1. **サーバーに接続し、新しいtmuxセッションを作成**
   ```bash
   ssh [ユーザー名]@[サーバーのIPアドレス]
   cd chuni_news_bot
   tmux new -s scraping
   ```

2. **仮想環境を有効化**
   ```bash
   source venv/bin/activate
   ```

3. **スクレイピングの起動**
   以下のコマンドを実行するだけで、即座に1回目が実行され、以降は毎日深夜0時に自動更新されます。
   ```bash
   python3 scraper.py
   ```

4. **デタッチしてバックグラウンドで動かす**
   実行状態のまま `Ctrl + B` → `D` を押して画面から抜けます。
   
※次回以降、スクレイピングの様子を確認したり止めたい場合は、`tmux attach -t scraping` で入ることができます。
